# ai_news_ops — 更新作業の自動化

毎回の更新でトークンを用意する必要をなくすための仕組みです。
認証は GitHub Actions が自動で用意する `GITHUB_TOKEN` を使うため、
個人アクセストークン（PAT）の発行・登録・貼り付けは一切不要になります。

---

## 毎回の更新手順（3ステップ）

1. Claude に「新規ニュースの更新をお願いします」と依頼する
2. Claude が出した記事のJSONを、リポジトリの `incoming.json` に貼り付けてコミットする
   （GitHubのWeb画面で `incoming.json` → 鉛筆アイコン → 貼り替え → Commit changes）
3. 数十秒待つ。あとは自動で終わります

コミットすると **ニュース更新** ワークフローが自動で走り、次の処理をまとめて行います。

- `incoming.json` の記事を検証する（形式・分野名・禁止語）
- 新しい記事を `news.json` の先頭に追加する
- 掲載期間を過ぎた記事を `archive-YYYY-MM.json` へ移動する
- `archive-index.json` を全月次ファイルから作り直す
- `index.html` の `updatedAt` を当日のJST日付に書き換える
- `incoming.json` を空に戻す
- 変更をコミットして公開する（GitHub Pages のビルドは自動）

触るファイルは `incoming.json` の1つだけです。

---

## 実行結果の確認

リポジトリの **Actions** タブ → **ニュース更新** → 最新の実行を開くと、
処理件数と警告がまとめて表示されます。

```
基準日 2026-09-04 / 掲載範囲は 2026-09-02 以降（2営業日）
incoming.json: 6件 検証OK
news.json: 12件（新規6 / 継続6 / アーカイブへ5）
   archive-2026-08.json: 71件（+5）
archive-index.json: 2026-08(71)・2026-07(168)・2026-04(1) / 日付44種 計240件
index.html updatedAt: 2026年9月4日（金）
```

`!!` で始まる行は警告です。処理は止まりませんが、内容を確認してください。

`incoming.json` の形式に問題があると、**何も書き換えずに停止**します。
理由が1行ずつ表示されるので、直して再度コミットしてください。

## 手動で動かす

Actions タブ → **ニュース更新** → **Run workflow**。
`書き込まずに結果だけ確認する` にチェックを入れると、
ファイルを変更せずに処理内容だけ確認できます（dry-run）。

新規記事がない日でも、アーカイブ整理と最終更新日の付け替えだけ実行できます。

---

## 手元で動かす

```bash
python3 scripts/ai_news_ops.py --dry-run          # 結果だけ確認
python3 scripts/ai_news_ops.py                    # 実行
python3 scripts/ai_news_ops.py --date 2026-09-04  # 基準日を指定（動作確認用）
```

## 設計上の約束ごと

- **祝日と掲載日数は `app.js` を唯一の情報源とする。**
  スクリプトは `app.js` の `FRONT_BUSINESS_DAYS` と `HOLIDAYS` を読み取って動くため、
  年末に祝日を足すときは `app.js` だけ直せば両方に反映されます。
- **`archive-index.json` は毎回すべての月次ファイルから作り直す。**
  部分的に足し引きすると件数がずれるため、差分更新はしません。
- **同じ記事は二重に入らない。** 日付と見出しが一致する記事は取り込みを飛ばします。
- **`topReason` は最新の1件だけ残す。** 新しい記事にトップ指定があると、
  フロントに残る既存記事の `topReason` は自動的に外れます。
  アーカイブへ移る記事の `topReason` はそのまま保存されます。
- **`newDays` と既存記事の禁止語は警告のみ。** 自動では書き換えません。

---

## 最初の1回だけ必要な設定

リポジトリの **Settings** → **Actions** → **General** →
**Workflow permissions** で **Read and write permissions** を選んで保存してください。

これがないと、ワークフローが変更をコミットする段階で
`403` エラーになります。

## incoming.json の書式

```json
[
  {
    "date": "2026-09-04",
    "category": "業務ツール",
    "title": "見出し",
    "summary": "2〜4文の要約。",
    "hint": "注目ポイント（不要なら空文字）",
    "terms": [
      { "word": "用語", "desc": "平易な日本語での説明。" }
    ],
    "topReason": "トップに据える記事だけに付ける（1〜2文）",
    "source": { "label": "媒体名（日付）", "url": "https://..." }
  }
]
```

- `postedAt` は書かなくて構いません。実行日が自動で入ります。
- `category` は次から選びます。
  法規制・権利／人材・組織／経営・投資／業務ツール／海外の動き／産業動向／SNSの話題／成功事例
- 使えない語：マーケター、マーケッター、当社、担当者視点
